# Api Contracts

Use for public/internal API creation or change. Examine existing endpoints and consumers first. Define ownership, operation, schema, status codes, pagination and filtering, authentication/authorization, tenant isolation, validation, error contracts, idempotency, rate limits and audit. Produce OpenAPI or existing-project canonical schema plus example payloads. Include backward compatibility and consumer migration plan for breaking changes. Verify contract tests and negative authorization cases; route privacy/security-impacting changes to relevant gates. Do not implement a speculative endpoint without a documented use case.

## Completion evidence
Report concrete files, tests, observed results and unresolved blockers. Follow the canonical registry and project-specific rules.
