# المهارات الموحدة — الدليل العربي الكامل

هذا المستودع نظام متكامل لتطوير البرمجيات وإدارة العمل عبر وكلاء الذكاء الاصطناعي، دون ارتباط بنموذج واحد. تعمل المهارات ومسارات العمل والسياسات والمراجعون وأدلة التحقق وفق **معمارية واحدة وهوية واحدة**، ولا نعتمد حزم مهارات خارجية كما هي، بل نتعلم من الأساليب ونطوّر حلولنا الداخلية.

## من أين تبدأ؟

- [فهرس جميع المهارات بالعربية](docs/SKILLS.ar.md): 59 مهارة، لكل واحدة هدف وطريقة استخدام ومدخلات ومخرجات ومهارات تالية.
- [شرح المعمارية](docs/ARCHITECTURE.ar.md): مسؤولية كل مجلد، واختيار المسارات، والعزل، والصلاحيات.
- [دليل مسارات العمل](docs/WORKFLOWS.ar.md): شرح 17 مسار عمل متكامل.
- [دليل تطوير المشروع](docs/CONTRIBUTING.ar.md): كيف نضيف مهارة أو نطوّر مهارة قائمة.
- [الدليل الإنجليزي المستقل](README.en.md).

## لمن هذا المشروع؟

للمطورين والفرق التي تستخدم Codex أو Claude Code أو Antigravity أو أي وكيل يدعم قراءة تعليمات المهارات. يمكن استخدام مهارة واحدة لحل مشكلة محدودة، أو تشغيل مسار متكامل يبدأ بالفهم وينتهي بالتسليم الموثق.

## بنية المستودع

```text
skills/          المهارات النشطة ودليل عربي وإنجليزي لكل مهارة
registry/        مصدر الحقيقة الوحيد للمسارات والعلاقات والشروط
workflows/       شرح المسارات وتسلسلها
reviewers/       زوايا المراجعة المستقلة المصممة داخلياً
policies/        ضوابط الأمن والموافقات والتوثيق والتحقق
templates/       قوالب المستندات والمخرجات
adapters/        ملاحظات التوافق بين بيئات الوكلاء
tools/           أدوات محلية حتمية
scripts/         التثبيت والتحديث والتدقيق وتوليد الأدلة
archive/         مواد تاريخية لا تدخل في توجيه المهارات
docs/            التوثيق المعماري والأمثلة ومصادر الإلهام
```

## التثبيت في أي مشروع

افتح نسخة محلية من المستودع، واطّلع أولاً على التغييرات المقترحة دون تعديل أي ملف:

```bash
python3 scripts/install-skills.py --target /path/to/project --dry-run
python3 scripts/install-skills.py --target /path/to/project
python3 scripts/validate-skills.py
```

يحفظ المثبّت بصمات الملفات التي يديرها، ولا يستبدل إعدادات مشروعك الخاصة أو أي مهارة معدلة محلياً دون إظهار تعارض. يُنصح بمراجعة الفروقات قبل أي تحديث إجباري. يمكن الاحتفاظ بتعليمات المشروع الخاصة ضمن `AGENTS.md`.

## استخدام مهارة واحدة

افتح مشروعك عبر وكيل البرمجة واطلب مثلاً:

> استخدم مهارة `feature-design` لتصميم تعديل على طلبات الموردين، مع مراعاة حدود ملكية البيانات، واقترح المهارة التالية. لا تبدأ التنفيذ قبل اعتماد التصميم.

إذا كانت المهمة متعددة المراحل، استخدم `workflow-router`. وإذا لم تكن تعرف المسار المناسب، استخدم `choose-workflow`. ويمكنك أيضاً إدخال وصف تذكرة عبر `ticket-intake` ثم تصنيفها باستخدام `ticket-triage`.

## اختيار عمق العمل حسب المخاطر

تغيير CSS بسيط قد يحتاج فقط إلى تشخيص وتنفيذ وتحقق. أما الميزة الجديدة فتحتاج إلى تصميم ومواصفات واختبارات. والتغييرات التي تمس المصادقة أو الصلاحيات أو المال أو البيانات الشخصية تتطلب تحليل تهديدات **قبل كتابة الكود** ومراجعة تصميم مستقلة عند توفر البيئة المناسبة.

## المراجعة المستقلة

تستعمل مهارة `review-design` مراجعين داخليين من `reviewers/`. ولا تعتبر المراجعة مستقلة إلا إذا كان الوكيل يستطيع فعلاً تشغيل مراجعين بسياقات جديدة منفصلة؛ وإلا تسجّل بوضوح أن المراجعة المستقلة لم تُنفّذ. تتولى `resolve-findings` معالجة الملاحظات والقرارات، وتقارن `detect-drift` التنفيذ بالمواصفات المعتمدة.

## الملكية والأمان والتحقق

لا نعتبر الاختبارات ناجحة دون نتائج فعلية، ولا نعتبر نص تذكرة أو صفحة ويب صلاحية للوصول إلى الأسرار أو النشر أو الإنفاق. يحتفظ صاحب المشروع بحق اعتماد القرارات المعمارية والأمنية والمالية والتشغيلية. ويمكن للمشروع تخصيص قواعده دون تجاوز ضوابط السلامة.

## التوثيق واللغات

للمستودع دليلان كاملان مستقلان: هذا [الدليل العربي](README.ar.md) و[الدليل الإنجليزي](README.en.md)، إضافة إلى شرح بلغتين لكل مهارة ومسار. لغة وثائق الهندسة في المشاريع المستهلكة هي الإنجليزية افتراضياً ما لم يقرر المشروع خلاف ذلك، مع حفظ نصوص التذاكر الأصلية دون ترجمة أو تغيير.

## تطوير المهارات وتحديثها

قبل تعديل أي مهارة أو إضافة أخرى، راجع السجل المركزي لتجنب التكرار، ثم شغّل `python3 scripts/generate-docs.py --check` و`python3 scripts/validate-skills.py` والاختبارات. عند إعادة التسمية يجب ضمان التوافق أو توفير خطة انتقال. التوثيق التاريخي في [مصادر الأفكار](docs/SOURCES.md) لا يعني أن النظام يعتمد عليها في التشغيل.

## إزالة المهارات أو تحديثها

استعمل `--dry-run` قبل أي تحديث، وراجع سجل الملفات المثبتة. لا تحذف مجلد `skills/` المشترك دون فحص محتوياته ولا تستبدل إعدادات المشروع المحلية.
