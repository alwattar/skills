# Accessibility Audit

Use for frontend features, landing pages and UI reviews. Check semantics, labels, headings, keyboard access, visible focus, color contrast, responsive and zoom behavior, reduced motion, error announcements, screen-reader naming and RTL/localization. Reference the project's agreed WCAG target, default to WCAG 2.2 AA as a proposed target unless already approved. Test with tools AND manual keyboard checks; accessibility automation cannot prove accessibility. Produce findings with severity, reproducible steps and regression tests.

## Completion evidence
Report concrete files, tests, observed results and unresolved blockers. Follow the canonical registry and project-specific rules.
