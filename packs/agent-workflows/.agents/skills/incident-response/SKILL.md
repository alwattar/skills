# Incident Response

Use only for a suspected operational or security incident. First establish severity, affected assets, timeline and evidence retention. Contain with least destructive reversible steps authorized by incident commander; do not delete logs or perform risky production operations without approval. Identify secrets and session rotation needs without printing credentials. Propose customer/regulator notification decisions to qualified owners, not automatic notices. Provide timeline, indicators, recovery checklist, monitoring, lessons and verified completion evidence. Distinguish observed compromise from speculation.

## Review output
List evidence, severity, affected boundary, verification and explicit open decisions. Obey project authorization and registered workflows.
