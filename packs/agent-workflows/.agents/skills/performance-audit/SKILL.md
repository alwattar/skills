# Performance Audit

Use for web/API/system latency and load changes. Define measurable baseline and target (Core Web Vitals, server latency percentiles, bundle size, throughput, DB timings as appropriate); segment by device/traffic and avoid invented results. Investigate trace/profile/query-plan evidence first. Optimize one bottleneck at a time with before/after measurements and regression checks. Verify SSR, cache correctness, SEO, accessibility, and memory. Keep perceived performance separate from backend throughput. Report measurement environment and uncertainty.

## Completion evidence
Report concrete files, tests, observed results and unresolved blockers. Follow the canonical registry and project-specific rules.
